## 1. 공통 구조 + 자동 시험 (63화면에 한 번에 적용)

### 1-1. 틀 = 안쪽 창 + 맨 위 틀 그림 → 「튀어나옴」 없애기
- **원인:** 지금은 금테 틀과 안의 그림(초상·전신·아이콘·글씨)을 따로 배치한다. 그래서 그림이 틀 장식 위로, 또는 틀 밖으로 나간다.
  - 예: 전투 카드 초상, 상점 코스튬 카드, 영웅 정보 큰 그림, 결투장 카드
- **고치는 방법:** 틀 있는 모든 부품을 같은 구조로 만든다.
  ```
  .framed  (크기 고정)
   ├ .framed-in   inset 만큼 안쪽 · overflow:hidden · 내용은 여기에만
   └ .framed-frame  틀 그림 · 맨 위 · pointer-events:none
  ```
  - inset은 틀 그림마다 숫자 하나로 정한다. 그림의 금테 안쪽 선까지 잰 값이다.
- **적용할 곳:**
  - 전투 아래 영웅 카드, 피해량 미터
  - 영웅 카드: 목록·편성·상점·결투장·외전 모두
  - 코스튬 카드, 아이템·장비 칸
  - 줄: 미션·업적·이정표·우편·친구·랭킹·길드
  - 결과 통계판·보상 카드
  - 영웅 정보 위 판, 스테이지 정보 창, 팝업 전부
- **T1 시험:** 모든 화면에서 `.framed-in` 안의 자식 사각형이 창 밖으로 1px이라도 나가면 실패한다.

### 1-2. 글씨체 하나
- **원인:** `tokens.ts` 글꼴 변수가 5개다. base는 Noto Serif 명조, title은 Hahmlet 명조, numUi는 Cinzel, 그리고 hero와 menu가 따로 있다. CSS 70곳이 이 5개를 섞어 쓴다.
- **바꾸는 것:**
  - 5개를 `--f-ui` 하나로 합친다.
  - Noto Serif KR, Cinzel, Hahmlet을 index.html에서 지운다.
  - 캔버스 글씨도 같은 글꼴을 쓴다: 머리 위 이름, 경고 문구, 페이즈 문구, 부위 이름.
  - 예외는 전투 피해 숫자(Luckiest Guy) 하나뿐이다.
  - 숫자에는 `tabular-nums`를 쓴다.
- **T2 시험:** CSS·TS·캔버스 `ctx.font`에 다른 글꼴이 나오면 실패한다.
- **견본:** 가장 먼저 견본 3종(A Gothic A1 800 / B Do Hyeon / C Jua)을 미션·전투·상점·영웅 정보 4화면으로 캡처해 보고하고 **멈춘다.** 형철이 고르면 `--f-ui` 한 줄만 바꾼다.

### 1-3. 스크롤바 0개

## 10. 수정 사항 (10/18 12:30 · 형철 요청문 반영 — 앞 내용과 다르면 이 절이 이긴다)

### 10-1. 스크롤바: 숨겨서 해결하지 않는다 (1-3 대체)
- 의도하지 않은 넘침(가로 스크롤, 판보다 큰 내용)을 **원인부터** 없앤다. 전역 `overflow:hidden`이나 스크롤바 숨김으로 가리지 않는다.
- 스크롤이 꼭 필요한 목록(영웅 목록, 상점 목록, 능력치, 미션 등)은 스크롤을 유지한다.
  - 휠, 터치, 키보드로 모두 움직일 수 있어야 한다.
  - 스크롤 트랙은 **장식 틀 안쪽**에 두고, 얇은 남색과 금색으로 꾸민다. 브라우저 기본 흰·회색 막대는 쓰지 않는다.
  - 바깥 틀은 고정하고 안쪽 내용만 움직인다.
- T3 시험을 바꾼다.
  - 가로 스크롤이 생기는 요소가 있으면 실패한다.
  - 세로 스크롤은 「스크롤 영역」으로 지정한 요소에서만 허용한다.

### 10-2. 글씨체: 역할 2개 (1-2 대체)
- 제목용 글꼴 1종: 화면 제목, 리본, 큰 이름.
- 본문·숫자용 글꼴 1종: 형철이 고른 견본.
- 그 밖의 글꼴은 금지한다(T2). 예외는 피해 숫자 하나뿐이다.
- 실제로 불러온 한글 글꼴과 대체 글꼴(fallback)을 확인하고 보고한다.
- 크기, 행간, 굵기, 외곽선 규칙을 공통 변수로 정한다. 단계는 5개 이하로 둔다.
- 제목 글꼴 후보는 본문 글꼴 결정 뒤에 견본 2개로 보여 주고 고르게 한다.

### 10-3. 잘림: 줄이거나 말줄임으로 숨기지 않는다 (1-4 대체)
- 긴 이름이나 숫자가 들어갈 자리를 레이아웃에서 먼저 확보한다. 그래도 넘치면 두 줄로 쓴다.
- 글씨 자동 축소는 원래 크기의 90%까지만 허용한다.
- **시험용 상태**를 만들어 63화면 캡처를 이 상태로도 한 번 더 찍는다.
  - 가장 긴 영웅 이름(「왈왈콩선생」, 「딸기망고모찌」)
  - 재화 9,999,999,999
  - 가장 긴 스킬·소개글
  - 레이드 8인

### 10-4. 원인 진단 먼저 (새로 추가 · 묶음 C 첫 단계)
- 틀·버튼·패널에 쓰는 모든 그림을 검사한다.
  - 알파 채널이 있는가
  - 불투명한 사각 바탕이 있는가
  - 투명 여백은 얼마인가
  - 실제 장식이 차지하는 영역은 어디인가
- 결과를 표로 정리한다: `docs/ASSET_CHECK_1018.md`.
- 표에서 「그림을 고쳐야 할 것」은 파일 이름과 필요한 처리(배경 따기, 여백 자르기, 구멍 마스크 만들기)를 적어 Claude에게 넘긴다. Code가 그림을 직접 고치지 않는다.
- 「코드로 고칠 것」은 아래 원인을 찾아 해당 파일·줄을 적는다.
  - 부모 요소의 background·border가 그림 밖으로 비침
  - 고정·최소 크기, padding, box-sizing 문제
  - 비율을 무시하고 늘어남
- 추정으로 CSS를 덧붙이지 않는다.
- 이미 알려진 예:
  - 상점 금색 구매 버튼 밖 노란 사각 바탕
  - 미션 줄 틀 밖 회색 면
  - 전투 카드 초상의 네모 경계

### 10-5. 초상화는 틀의 실제 구멍 모양으로 자른다
- 둥근 모서리(border-radius)로 대충 깎지 않는다.
- 틀 그림의 구멍 모양을 마스크 그림으로 만들어 `mask-image`로 자른다. 마스크는 그림 쪽에서 만들 수 있으니 10-4 표에 「마스크 필요」로 적는다.

### 10-6. 늘이기 금지
- 크기가 바뀌는 판은 9-slice(border-image)나 모서리·변 분리 방식으로만 늘인다. 틀 그림 전체를 통째로 늘이지 않는다.
- 고정 비율 HUD(전투 카드 등)는 안의 요소와 같은 기준으로 함께 확대·축소한다.
- 장식 층은 `pointer-events:none`으로 둔다.
