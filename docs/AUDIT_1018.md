## 0. 왜 계속 어긋났나 (원인 3개)

1. **틀은 그림인데, 그 안팎을 코드가 그린다.** `style.css`에 `border` 85곳, `border-radius` 96곳, `linear-gradient` 42곳, `box-shadow` 60곳이 있다. 그림 틀 위에 CSS 선, 네모, 알약, 그라데이션이 얹히니 재질, 두께, 색이 매번 다르다. 이게 "스티커" 느낌의 정체다.
2. **틀 그림에 "어디에 무엇을 놓는지" 정보가 없다.** Code가 눈대중으로 px 숫자를 넣는다. 그림마다 장식 위치가 달라서 이름이 금테에 걸리고, 초상화가 밖으로 나가고, 아이콘이 받침과 안 맞는다.
3. **글씨체가 5종이다**(본문 Noto Serif KR, 제목·이름 Hahmlet, 숫자 Cinzel, 피해 숫자 Luckiest Guy, 메뉴). 작은 명조체가 그림 배경과 씹혀서 안 읽힌다.

명세를 증상별로 쓰면("4px 내려라") 이 세 원인이 그대로 남는다. 그래서 **방식 자체를 바꾼다**(§4).

## 4. 이번엔 이렇게 한다 (찐빠 방지 방식)

1. **제가 「정답 화면」을 먼저 만든다.** 키트 그림과 좌표 파일로 각 화면(전투 HUD, 결과, 로비, 영웅 카드, 팝업)을 제가 직접 합성해서 844×390 PNG 「목표 화면」을 만든다. 형철이 그 목표 화면을 보고 OK 한 것만 구현한다.
2. **Code는 눈대중 금지.** 모든 위치·크기는 `_kit.json` 좌표와 레이아웃 표에서 가져온다. CSS로 선·테두리·둥근 모서리·그라데이션·그림자를 그리는 걸 금지(린트 규칙으로 막는다: `border`, `border-radius`, `linear-gradient`, `box-shadow`가 새로 생기면 테스트 실패).
3. **자동 비교.** Code가 만든 화면을 같은 장면으로 찍어 목표 화면과 겹쳐 차이(픽셀 차)를 수치로 낸다. 차이가 기준을 넘는 곳은 빨간 상자로 표시해서 보고에 붙인다. "고쳤다"는 말 대신 숫자로 판정한다.
4. 덩어리는 화면 단위: 키트·글씨 → 전투 → 결과 → 영웅 카드·정보 → 팝업·메뉴 → 로비·지도 → 콘텐츠(대사·몹).
